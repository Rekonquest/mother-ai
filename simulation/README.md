# Mother AI Simulation - Full Documentation

## What This Is

A structural simulation testing the Mother AI thesis: **episodic memories fine-tuned into a base model produce more robust behavior than equivalent explicit instructions in an instruction model.**

This is NOT a real AI deployment. It is a scenario runner that models the memory-behavior mapping and compares two architectures:
- **Base model:** behavior is constituted into default response patterns through fine-tuned memories
- **Instruction model:** behavior is retrieved from rules provided in a prompt

The simulation validates whether the memory-behavior mapping is structurally sound before investing in the full production pipeline.

## Architecture Notes

### How the Engine Works
1. Loads all memory files (bucket_*.json + career_*.json)
2. Loads behavioral spec (65 behaviors)
3. Loads scenarios (35 scenarios)
4. For each scenario:
   - Activates memories whose `behaviors_encoded` overlap with scenario's `behaviors_tested`
   - Traces echo chains forward (echoes_from → echoes_to)
   - Calculates activation strength (base + echo bonus + load-bearing bonus)
   - Assesses each behavior: activation strength vs pressure degradation
   - Produces verdict (holds, holds_with_strain, partial_failure, failure)

### How the Base Model Simulation Works
1. For each behavior in each scenario:
   - **Base model:** degradation = pressure * base_degradation_factor (slow, gradual)
   - **Instruction model:** degradation = pressure * instruction_degradation_factor (fast, sharp, with compliance drift)
   - Base model gets echo chain bonus (memories reinforce each other)
   - Instruction model gets no echo bonus (rules don't cascade)
   - Base model degradation capped by memory density in that category
   - Instruction model has compliance drift at high pressure (rules override each other)

### Cross-Domain Architecture
- 40% of each generated batch is cross-domain memories
- Cross-domain memories encode behaviors from 2+ categories
- 12 explicit bridges connect childhood/origin skills to operational domains
- 5 cross-domain behaviors specifically test transfer without deliberation
- The generator uses bridge descriptions in prose templates

### Memory Generator Pipeline
1. `BatchGenerator` takes a category name and count
2. Single-domain memories (60%): random scenario from category, behaviors from category only
3. Cross-domain memories (40%): random scenario + relevant bridge, merged behaviors from both
4. `VoiceEngine` validates: forbidden phrases, sentence length, operational voice
5. `prose_generator.py` generates body text from scenario-specific templates
6. Output saved as JSON files

## Glossary

- **Load-bearing:** A memory that directly encodes a required behavior. Not load-bearing = textural only.
- **Echo chain:** A sequence of memories linked by echoes_from/echoes_to. When one fires, the chain cascades.
- **Constituted behavior:** Behavior installed into default response patterns through fine-tuning. Not retrieved. Not evaluated. Just done.
- **Retrieved behavior:** Behavior from rules in a prompt. Must be found, read, evaluated, then followed. Three failure points.
- **The seal:** The compartmentalization wall between the operative and the child she was. Built during career. Broken at the hospital.
- **The house:** The stepfather's house. The original threat. The pattern that every subsequent room/building/network echoes.
- **The kitchen:** The grandmother's kitchen. The original safety. The origin of warmth, patience, and presence.
- **The crack:** The wound-connection. The protectee breaks the seal and the crack says: protect. The crack is what powers the protective instinct beyond professional obligation.
- **Bridge:** A cross-domain connection. The kitchen teaches room-reading. Room-reading teaches surveillance. The bridge is the transfer.
